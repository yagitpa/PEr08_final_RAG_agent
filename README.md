# Ассистент студента Зерокодера

RAG-ассистент по конспектам курса промпт-инжиниринга. Отвечает на вопросы строго
по базе знаний, собранной из конспектов уроков, и умеет сказать «в базе этого
нет» вместо того чтобы выдумать ответ.

Итоговый проект модуля 5 «Ассистенты с памятью: базы знаний, RAG и Relevance».

## Архитектура

Система разделена на четыре независимых конвейера, связанных артефактами на
диске, а не общими объектами в памяти:

| | Конвейер | Что делает |
|---|---|---|
| **P1** | Авторство | Страница урока или файл (PDF/HTML/DOCX) → конспект `.md` |
| **P2** | Индексация | Конспекты → очищенные чанки → векторное хранилище |
| **P3** | Запрос | Вопрос → эмбеддинг → поиск → отбор контекста → LLM → ответ |
| **P4** | Оценка | Golden set → метрики качества поиска и ответов |

Полное описание с обоснованием решений — в [docs/architecture.md](docs/architecture.md).

Конвейер запроса:

```
вопрос -> кэш ответа -> эмбеддинг -> поиск (top_k x overfetch)
       -> порог релевантности -> дедупликация -> срез top_k
       -> сборка контекста -> LLM -> ответ + источники
```

## Состояние

Реализован **этап 1 — препроцессинг** (`src/zerocoder_assistant/preprocessing/`).
Остальные этапы описаны в архитектуре и ещё не написаны.

Что уже работает:

- разбор Markdown с учётом fenced-блоков (комментарий `#` в листинге не считается
  заголовком, пустая строка внутри ``` не рвёт блок);
- отбор секций по настраиваемому списку — служебные разделы отбрасываются,
  незнакомый заголовок сохраняется;
- очистка текста: эмодзи, HTML-теги, разметка, невидимые символы, схлопывание
  пробелов; варианты тире приводятся к одному символу, а не удаляются;
- структурный чанкинг по токенам с перекрытием целыми предложениями,
  contextual header и неделимыми листингами;
- слияние мелких соседних секций-сестёр;
- метаданные из пути, имени файла и заголовка (frontmatter, если есть,
  переопределяет выведенное).

## Установка

```bash
python -m venv .venv
```

```bash
.venv\Scripts\activate
```

```bash
pip install -e ".[dev]"
```

```bash
copy .env.example .env
```

В `.env` укажите `NOTES_DIR` — путь к папке с конспектами. Она может лежать вне
проекта. Ключи API понадобятся начиная с этапа 2.

## Использование

Посмотреть, как корпус разбивается на чанки, — сводка, гистограмма размеров и
примеры:

```bash
zassist index preview
```

Только один урок, с выгрузкой чанков в JSONL:

```bash
zassist index preview --lesson PEr08 --export chunks.jsonl
```

Все команды и опции:

```bash
zassist --help
```

## Разработка

```bash
pytest
```

```bash
ruff check src tests && ruff format --check src tests
```

Интеграционные тесты идут по реальному корпусу и автоматически пропускаются,
если `NOTES_DIR` недоступен.

## Структура

```
src/zerocoder_assistant/
├─ config/          настройки из окружения и предметные константы
├─ preprocessing/   разбор Markdown, очистка, чанкинг, метаданные
├─ reporting.py     агрегаты и текстовые отчёты
└─ cli/             команды терминала
docs/architecture.md   архитектурное решение целиком
tests/                 модульные тесты и прогон по реальному корпусу
```

Всё, что можно вынести, вынесено: пути, размеры, пороги и модели — в `.env`,
предметные списки и регулярные выражения — в `config/constants.py`. В корне
проекта только конфигурация и документация.

## Первая команда

Разовый вопрос:

```bash
zassist ask "как работает кэширование в RAG"
```

Или диалог, если вопросов несколько подряд:

```bash
zassist ask --repl
```

```
Диалог с ассистентом. Память держит последние 5 пар реплик.
/clear — забыть диалог, /exit — выйти, /help — справка.

вопрос>
```

Дальше просто пишите вопросы. Выйти — `/exit`.

## Как читать ответ

```
Порог релевантности (Score Threshold) — это настройка, которая определяет,
насколько высоким должно быть совпадение вектора запроса с вектором в базе,
чтобы чанк был извлечён и использован [3].

Источники:
  1. PEr06 > Результат дня
  2. PEr06 > 6. Практический пример: тестирование RAG-системы (часть 5/8)
  3. PEr08 > 4. Параметры RAG (часть 2/2)
```

- **`[3]` в тексте** — номер фрагмента, из которого взято это утверждение.
  Смотрите строку 3 в списке источников: там урок и раздел.
- **`PEr08 > 4. Параметры RAG`** — идентификатор урока и путь заголовков.
  По нему открывают сам конспект и читают полностью.
- **`(часть 2/2)`** — раздел был длинный и разрезан на части; это вторая.

Список источников печатает программа по фактически отобранным фрагментам, а не
модель. То есть источники нельзя выдумать: они всегда те, что реально попали в
контекст.

Утверждение **без номера** — это связка или переформулировка, а не факт из
конспектов. Числа, версии, названия и код всегда идут со ссылкой.

Хотите увидеть, как ответ собирался:

```bash
zassist ask "что такое порог релевантности" --verbose
```

```
Отбор:    кандидатов 15 | ниже порога 0 | дублей 0 | отобрано 5
Контекст: 5 фрагм. | 1502 ток.
Время:    embed 3030 мс | search 6 мс | context 1 мс | llm 1453 мс | total 4508 мс
```

## Три вида ответов и что с ними делать

**1. Ответ по существу.** Фрагменты покрывают вопрос, каждое утверждение со
ссылкой. Ничего делать не нужно.

**2. Ответ с оговоркой.** Часть есть, часть — нет, и ассистент прямо говорит,
чего именно не нашлось:

```
Размер чанка задаётся параметром CHUNK_TARGET_TOKENS [1]. Чем обосновано
именно значение 400 токенов — во фрагментах не сказано.
```

Оговорка — это не недоработка, а отказ выдумывать. Если недостающее важно,
попробуйте спросить отдельно и другими словами.

**3. «В конспектах этого нет».** Два разных случая, и различать их полезно:

```
В конспектах этого нет. Рядом лежит информация о кэшировании [1], [2].
```

Здесь фрагменты нашлись, но темы среди них нет. Перечисленное рядом — подсказка,
что искать дальше.

```
В конспектах ничего подходящего не нашлось.
Попробуйте переформулировать вопрос ближе к словам из урока или снимите
фильтры, если задавали их.
```

Здесь не нашлось вообще ничего похожего — языковая модель даже не вызывалась,
запрос ничего не стоил. Чаще всего дело в формулировке, см. следующий раздел.

> Отказ — это рабочий ответ, а не сбой. Ассистент, который на любой вопрос
> уверенно отвечает, бесполезен: проверять придётся каждое слово.

## Как формулировать вопрос

Поиск идёт **по смыслу**, а не по словам, так что точную формулировку из
конспекта помнить не нужно. Но кое-что заметно влияет на результат.

**Голый английский термин работает хуже, чем термин с русским пояснением.**
Корпус русскоязычный, и одинокое английское слово может увести не туда:

```bash
zassist search "что такое overlap"
```

```
1. [0.323] PEn04 > 2. Нода Merge: объединение параллельных потоков
```

Не то: «overlap» оказался ближе к «объединению потоков», чем к чанкингу.
Добавьте русское слово:

```bash
zassist search "overlap перекрытие чанков"
```

```
1. [0.392] PEr03 > 8. Пайплайн подготовки данных: чанкинг
```

**Спрашивайте словами предметной области.** «Как сделать, чтобы бот не врал» —
хуже, чем «как уменьшить галлюцинации»: во втором варианте слова те же, что в
конспектах.

**Одна мысль — один вопрос.** Три вопроса в одном предложении размывают
эмбеддинг, и находится середина между тремя темами.

**Длина не помогает.** Развёрнутое вступление на пять строк не улучшает поиск:
в вектор идёт всё, и полезный сигнал в нём растворяется.

## Диалог и память

В режиме `--repl` ассистент помнит последние несколько пар реплик, поэтому
уточняющие вопросы работают:

```
вопрос> overlap перекрытие чанков
Перекрытие между соседними чанками обычно составляет 15–20% текста [3].

вопрос> а сколько его ставить?
В конспектах упоминается, что перекрытие обычно 15–20% текста [3].
```

Второй вопрос сам по себе бессмысленен — в нём нет ни одного слова о предмете.
Память подставляет тему предыдущего вопроса в поисковый запрос, и фрагменты
находятся.

Проверить, что память действительно работает, можно так:

```
вопрос> /clear
История очищена (забыто пар реплик: 2).

вопрос> а сколько его ставить?
В конспектах ничего подходящего не нашлось.
```

После `/clear` тот же уточняющий вопрос уже не понимается — и это правильное
поведение, а не поломка.

Команды диалога:

| Команда | Что делает |
|---|---|
| `/clear` | Забыть историю. Полезно при смене темы |
| `/help` | Список команд |
| `/exit` (или `/quit`) | Выйти |

Опечатка в команде (`/exti`) не уедет в модель как вопрос — ассистент скажет,
что команда неизвестна.

**Когда стоит сказать `/clear`:** вы сменили тему. Память подмешивает прошлую
тему в поиск, и после разговора про кэш вопрос «а как его настроить?» про
что-то другое найдёт снова кэш.

## Сузить поиск фильтрами

Если известно, где искать, фильтры экономят и время, и деньги:

```bash
zassist ask "оценка качества" --lesson PEr06
```

```bash
zassist ask "что такое эмбеддинг" --module 5
```

`--lesson` можно повторять: `--lesson PEr06 --lesson PEr07`.

Отдельно есть фильтр по типу содержимого:

```bash
zassist ask "как считать recall" --content-type code
```

| Тип | Что это |
|---|---|
| `theory` | Основное изложение |
| `practice` | Практические разделы и разборы |
| `code` | Фрагменты с листингами |
| `summary` | «Результат дня» — итог урока |
| `actualization` | Поздние поправки автора к устаревшему тексту |

`actualization` — самое свежее в корпусе: пины версий, изменившиеся статусы
сервисов. Если ответ кажется устаревшим, стоит переспросить с этим фильтром.

Расширить выдачу, когда ответ выглядит неполным:

```bash
zassist ask "как устроен чанкинг" --top-k 10
```

## Посмотреть, что вообще есть в базе

Команда `search` показывает найденные фрагменты **без обращения к языковой
модели** — она ничего не стоит и отвечает мгновенно:

```bash
zassist search "кэширование"
```

Удобна, когда нужно не объяснение, а сам текст конспекта, или когда хочется
понять, почему ассистент ответил именно так.

Что лежит в индексе целиком:

```bash
zassist index stats
```

```
Коллекция:             notes__text-embedding-3-small
Векторов в базе:       920
Модель эмбеддингов:    text-embedding-3-small (openai)
Чанков при сборке:     920 из 46 конспектов
Собран:                2026-08-19T09:56:26+00:00
```

## Добавить новые конспекты

**1. Положить файл** в папку с конспектами, соблюдая раскладку:

```
<папка конспектов>/
└─ Модуль 5. Ассистенты с памятью/
   └─ PEr09_Новый_урок.md
```

Имя файла должно начинаться с идентификатора урока (`PEr09`) — по нему
работают ссылки в ответах и фильтр `--lesson`. Название папки даёт модуль.

**2. Посмотреть, как файл разберётся** — бесплатно, без обращения к API:

```bash
zassist index preview --lesson PEr09
```

Стоит проверить, что чанки осмысленные, блоки кода не разорваны, а служебные
разделы («Домашнее задание», шапки) отброшены.

**3. Добавить в индекс:**

```bash
zassist index build
```

Векторизуется только новое и изменившееся: у каждого чанка есть отпечаток
содержимого, и знакомые пропускаются. Поэтому добавление одного урока к сорока
шести стоит копейки, а не как полная пересборка.

**Что произойдёт с правками и удалениями.** Если поправить существующий
конспект — переиндексируются только затронутые чанки. Если удалить файл —
его чанки уйдут из базы при следующей полной сборке. С `--lesson` удаление
отключено: команда работает только на добавление.

**Когда нужна полная пересборка.** Только при смене модели эмбеддингов или
параметров чанкинга:

```bash
zassist index build --rebuild
```

Смену модели ассистент и сам не пропустит: имя модели входит в имя коллекции и
записано в манифесте, поэтому запрос к индексу, собранному другой моделью,
даст внятный отказ, а не молчаливо неверную выдачу.

## Замерить качество

Качество меряется на наборе вопросов с заранее известными правильными ответами
(`docs/golden_set.yaml`): 51 вопрос, из них 11 — такие, ответа на которые в
конспектах нет.

```bash
zassist eval run
```

Эта команда **не вызывает языковую модель** — считается только качество поиска,
поэтому прогон почти бесплатный:

```
recall@1:            60%
recall@3:            75%
recall@5:            88%
MRR:                 0.695
ложных отказов:      0 из 40 (0%)
```

Как это читать:

| Метрика | Смысл | Куда смотреть |
|---|---|---|
| `recall@k` | Доля вопросов, где нужный урок попал в первые k фрагментов | Чем выше, тем лучше |
| `MRR` | Насколько высоко в выдаче стоит нужный урок | 1.0 — всегда первым |
| ложные отказы | Сколько раз система промолчала там, где ответ есть | Должно быть 0 |
| отказы там, где ответа нет | Сколько раз правильно отказала | Чем выше, тем лучше |

Прогон с ответами модели — проверяет, не ссылается ли она на несуществующие
фрагменты и не выдумывает ли на вопросах вне базы. Стоит денег:

```bash
zassist eval run --answers
```

Разобрать конкретные промахи построчно:

```bash
zassist eval run --export outcomes.jsonl
```

**Подобрать порог релевантности** — команда проходит корпус один раз и
показывает, что было бы при других значениях:

```bash
zassist eval threshold
```

**Метрики RAGAS** (нужно отдельно установленное окружение, см. README):

```bash
zassist eval ragas --limit 5
```

`--limit` здесь не лишний: RAGAS делает несколько вызовов модели на каждый
вопрос и на каждую метрику, так что полный прогон заметно дороже обычного.

> Одну метрику RAGAS стоит читать с оговоркой. `answer_relevancy` ставит ноль
> ответам, которые честно оговаривают, чего в конспектах не нашлось, — то есть
> штрафует ровно то поведение, ради которого оговорки и сделаны. Подробности —
> в [инженерном журнале](engineering_log.md).

## Кэш: почему второй раз мгновенно

Тот же вопрос второй раз отвечается сразу и бесплатно. Кэш трёхуровневый:
вектор запроса, результаты поиска и готовый ответ.

```bash
zassist cache stats
```

```
L1 эмбеддинги:         55
L2 результаты поиска:  52
L3 ответы:             97
Всего:                 204
Размер файла:          1404.0 КБ
```

Кэш **учитывает параметры**: сменили `--top-k` или фильтр — получите свежий
ответ, а не старый, посчитанный при других настройках. То же при смене модели
или правке промпта.

Получить заведомо свежий ответ:

```bash
zassist ask "вопрос" --no-cache
```

Очистить:

```bash
zassist cache clear --level answers
```

Уровни: `answers`, `retrieval`, `embeddings`. Без `--level` чистятся все.
Чистить обычно не нужно — разве что после правки конспектов, если хочется
убедиться, что ответ пересобран с нуля.

Ответы в диалоге с непустой историей **не кэшируются**: они зависят от
предыдущих реплик, а ключ кэша о них не знает.

## Настройки, которые меняют выдачу

Менять их не обязательно, но полезно понимать, что стоит за поведением. Живут
в файле `.env`, применяются со следующего запуска.

| Переменная | По умолчанию | Что будет, если изменить |
|---|---|---|
| `TOP_K` | 5 | Больше фрагментов в ответе; дороже и больше шума |
| `RELEVANCE_THRESHOLD` | 0.30 | Выше — чаще отказы, ниже — больше мусора в контексте |
| `HISTORY_PAIRS` | 5 | Сколько пар реплик помнит диалог; `0` выключает память |
| `MAX_CONTEXT_TOKENS` | 3000 | Бюджет контекста |
| `TEMPERATURE` | 0.2 | Выше — разнообразнее формулировки, менее предсказуемо |

Разовое изменение удобнее делать ключом (`--top-k 10`), а не правкой файла.

**Про порог отдельно.** Поднимать его, чтобы «система реже выдумывала», —
плохая идея: измерения показали, что смежные темы дают сходство выше, чем
некоторые правильные вопросы, и порогом эти случаи не разделяются. За отказ на
смежной теме отвечает не порог, а системный промпт.

## Если что-то пошло не так

| Симптом | Что это значит | Что делать |
|---|---|---|
| «В конспектах ничего подходящего не нашлось» | Ничего похожего не найдено | Переформулировать, добавить русские слова, снять фильтры |
| Ответ про другую тему | Запрос ушёл не туда | Уточнить формулировку; проверить `search` |
| Ответ кажется устаревшим | Взят старый раздел | Переспросить с `--content-type actualization` |
| Уточняющий вопрос не понят | История пуста или сменилась тема | Задать вопрос целиком, со словами о предмете |
| «Каталог конспектов не найден» | Не задан путь к конспектам | Заполнить `NOTES_DIR` в `.env` |
| «Пересоберите индекс» | Индекс собран другой моделью | `zassist index build --rebuild` |
| Новый конспект не находится | Он ещё не в индексе | `zassist index build` |
| Ответ не меняется после правки конспекта | Отдаётся кэш | `--no-cache` либо `cache clear` |

Полный список команд и ключей всегда под рукой:

```bash
zassist --help
```

## Чего ассистент не умеет

Честные границы, чтобы не тратить время:

- **Не знает ничего, кроме ваших конспектов.** Вопрос о том, чего в них нет,
  получит отказ, даже если модель знает ответ. Это сделано намеренно.
- **Не помнит разговор между запусками.** Закрыли терминал — история пуста.
- **Не ищет по точному совпадению слов.** Поиск смысловой; чтобы найти
  дословную строку, удобнее обычный `grep` по папке с конспектами.
- **Не считает и не сравнивает по всей базе.** Вопросы вида «в каком уроке
  больше всего примеров кода» требуют обхода всего корпуса, а ассистент видит
  только несколько отобранных фрагментов.
- **Не обновляет конспекты сам.** Новый урок нужно положить файлом и запустить
  сборку индекса.
- **Не работает с картинками и таблицами-изображениями** — только с текстом
  Markdown.

# Зависимости оценки через RAGAS.
#
# ЭТОТ ФАЙЛ НЕ СТАВИТСЯ В ОКРУЖЕНИЕ ЯДРА. Не «желательно не ставить», а нельзя:
# RAGAS требует langchain-openai, который держит openai на версии 2.x, тогда
# как ядро работает на 3.x. Проверено установкой в чистое окружение — клиент
# откатывается с openai 3.3.0 до 2.54.0, то есть подменяется ровно тот клиент,
# которым ядро делает каждый вызов модели и каждый запрос эмбеддингов.
#
# Поэтому окружения два, а связаны они файлом на диске: ядро пишет набор данных
# в JSONL, оценщик читает его своим интерпретатором. Ни одна библиотека границу
# не пересекает.
#
# --- Установка ---------------------------------------------------------------
#
#   py -3.14 -m venv .venv-eval
#   .venv-eval\Scripts\python.exe -m pip install -r requirements-eval.txt
#
# Затем прописать интерпретатор в .env:
#
#   RAGAS_PYTHON=./.venv-eval/Scripts/python.exe
#
# После этого работает `zassist eval ragas`. Без этой настройки команда честно
# скажет, чего не хватает, и завершится успехом — оценка необязательна.
#
# --- Почему именно эти версии ------------------------------------------------
#
# ragas 0.4.3 — свежая ветка, и она единственная работает на Python 3.14.
# Разбор веток целиком:
#
#   0.1.x  требует langchain-community<0.3, а та требует numpy<2. Колёс numpy<2
#          под 3.13/3.14 не существует: последний релиз ветки 1.x вышел раньше
#          этих версий. Установка уходит в сборку из исходников и падает без
#          компилятора C.
#
#   0.2.x  ставится и импортируется без единой жалобы, но НЕ СЧИТАЕТ НИЧЕГО.
#          Её executor безусловно вызывает nest_asyncio.apply() при импорте.
#          Патч ломает учёт задач: asyncio.current_task() начинает возвращать
#          None (проверяется одной строкой — до импорта ragas True, после
#          False), и внутренний asyncio.wait_for падает с
#              RuntimeError: Timeout should be used inside a task
#          RAGAS это исключение глотает, все метрики выходят nan, а скрипт
#          отрабатывает до конца. Именно этот случай — не ошибка установки, а
#          молчаливо пустой результат — и был здесь сначала.
#
#   0.4.3  применяет nest_asyncio только когда цикл событий уже запущен (то
#          есть в Jupyter), а в обычном скрипте asyncio не трогает. Сверх того
#          принимает allow_nest_asyncio=False, который отключает патч совсем;
#          оценщик передаёт его, если установленная версия такой параметр
#          принимает.
#
# langchain-community 0.3.27 — потому что ragas при загрузке импортирует
# ChatVertexAI, а из ветки 0.4.x этот модуль убрали:
#     ModuleNotFoundError: No module named 'langchain_community.chat_models.vertexai'
# Ошибка возникает на самом `import ragas`, поэтому try/except в коде проекта
# её не ловит — она случается раньше.
#
# scikit-network 0.12.1 — жёсткая зависимость ragas 0.4.3 (нужна только
# генератору синтетических тестов, который здесь не используется). Свежая
# ветка 0.33.x собрана колёсами для Windows только до cp313; на 3.14 pip лезет
# компилировать её из исходников и падает с «Microsoft Visual C++ 14.0 or
# greater is required». Версия 0.12.1 — чистый Python (колесо py2.py3-none-any),
# ставится на любом интерпретаторе и требование ragas закрывает. Когда появится
# колесо под cp314, пин можно снять.
#
# Проверено на CPython 3.14.4: установка одной командой без компилятора C,
# реальный прогон даёт числа, а не nan.

ragas==0.4.3
langchain-community==0.3.27
scikit-network==0.12.1
